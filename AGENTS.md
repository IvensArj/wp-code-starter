# Trabalhar neste starter

Este repositório entrega um tema de blocos WordPress e um plugin opcional de Projetos. Leia o [README](README.md) e inspecione o template, os padrões e os estilos atuais antes de começar.

- Use `theme.json` para tokens e controles de design, `templates/` para modelos, `parts/` para estrutura compartilhada e `patterns/` para trechos inseríveis. Use PHP, CSS e JavaScript do projeto e prefira APIs e blocos nativos do WordPress.
- Preserve a edição no Gutenberg. Títulos, textos, links e imagens de página pertencem a blocos. Use `post-content` no modelo, organize a hierarquia de títulos e coloque textos de interface traduzíveis no domínio do tema ou plugin.
- Mantenha atributos e marcação de blocos coerentes. Alterações nos controles de `metadata.wpcsVisual` devem produzir a mesma composição na prévia e no site. Escaneie os templates existentes antes de mudar slugs, tipos ou nomes de atributos persistidos.
- Use conteúdos iniciais de `demo/` para mostrar recursos. Preserve conteúdo e configurações de instalações existentes. Use dados fictícios e mídias redistribuíveis nos exemplos publicados.
- Inclua a apresentação de Projetos no tema e mantenha o tipo de conteúdo, a taxonomia e o filtro no plugin opcional. Teste o tema sozinho quando alterar recursos compartilhados.
- Ao conferir mudanças de estrutura, verifique se o Editor do Site tem uma personalização salva no banco para o mesmo modelo. Versione a marcação que precisa acompanhar o tema.
- Antes de entregar, reproduza a tarefa pelo fluxo normal. Abra o editor, altere um bloco, salve, reabra e confira o site em largura de desktop e celular. Execute os testes existentes quando a alteração atingir a instalação, os blocos ou a Galeria. Registre verificações que ficaram pendentes.
